# Workflow diagrams

Mermaid diagrams of how the study runs, from one task to a figure in the paper.
GitHub and VS Code (with a Mermaid preview) render them in place.

1. [Study pipeline](#1-study-pipeline): collection → features → evaluation → paper artifacts
2. [Deployment C orchestrator (LangGraph)](#2-deployment-c-orchestrator-langgraph): the `StateGraph`
   exported by LangGraph itself, and how its nodes map onto A2A calls per topology
3. [One traced task](#3-one-traced-task-chain-topology): what crosses the wire in a chain run

## 1. Study pipeline

```mermaid
flowchart TD
    P["Prompt pool<br/>4 workflow classes<br/>prompt_group = sha1(prompt)[:8]"]

    subgraph COLLECT["Collection (scripts/collect_deployment.py, collect_tls_session.py, ...)"]
        O["Orchestrator<br/>(in-process, driven by the collector)"]
        S["Specialist agents<br/>executor · retriever · validator<br/>a2a-sdk servers, JSON-RPC + SSE"]
        L["Ollama<br/>llama3.2:3b / qwen2.5:7b"]
        T["tcpdump on lo0<br/>snaplen 96"]
        O -- "A2A message/stream" --> S
        O -.->|local LLM call| L
        S -.->|local LLM call| L
        S -- "packets on agent ports" --> T
        O -- "packets on agent ports" --> T
    end

    P --> O
    T --> R["data/raw*/<br/>.pcap + .json label sidecar<br/>(workflow, topology, roles, prompt)"]
    R --> X["scripts/strip_payload.py<br/>headers only, for release"]
    R --> F["scripts/extract_features.py<br/>timing, sizes, directions, bursts,<br/>per-flow and per-trace features"]
    F --> D["data/processed*/"]

    D --> E1["Within-deployment<br/>grouped CV by prompt_group<br/>RF / GBT, cluster bootstrap CIs"]
    D --> E2["Transfers<br/>model vs logic, A↔B, A↔C,<br/>cross-network, prompt-disjoint cross-fit"]
    D --> E3["Defenses<br/>pad · rate, live and simulated"]
    D --> E4["Controls<br/>framework-ID, open world,<br/>TLS vs cleartext (same session)"]

    E1 & E2 & E3 & E4 --> J["data/results/*.json"]
    J --> M["scripts/make_paper_artifacts.py"]
    M --> G["figures/*.png and the paper's tables"]
```

## 2. Deployment C orchestrator (LangGraph)

Deployment C keeps A's specialist agents, prompts and model, and replaces only the
orchestrator's fan-out with a LangGraph `StateGraph`
([agents_langgraph/orchestrator_langgraph.py](../agents_langgraph/orchestrator_langgraph.py)).
`decompose` and `synthesize` are local Ollama calls that never reach the captured wire; each
`call_i` node is one A2A streaming call to a specialist, which is the traffic the observer sees.

### As exported by LangGraph

Generated by `python scripts/export_langgraph_mermaid.py`
(`get_graph().draw_mermaid()`; files in [docs/diagrams/](diagrams/)). Star topology:

```mermaid
---
config:
  flowchart:
    curve: linear
---
graph TD;
	__start__([<p>__start__</p>]):::first
	decompose(decompose)
	synthesize(synthesize)
	call_0(call_0)
	call_1(call_1)
	call_2(call_2)
	__end__([<p>__end__</p>]):::last
	__start__ --> decompose;
	call_0 --> synthesize;
	call_1 --> synthesize;
	call_2 --> synthesize;
	decompose --> call_0;
	decompose --> call_1;
	decompose --> call_2;
	synthesize --> __end__;
	classDef default fill:#f2f0ff,line-height:1.2
	classDef first fill-opacity:0
	classDef last fill:#bfb6fc
```

Chain has a single `call_0` and mesh has `call_0` and `call_1`
([langgraph_chain.mmd](diagrams/langgraph_chain.mmd), [langgraph_mesh.mmd](diagrams/langgraph_mesh.mmd)).
The edges out of `decompose` run in one parallel superstep; the edges into `synthesize`
are the fan-in barrier, and the `results` channel's additive reducer collects each branch's output.

### Mapped onto agents and the wire

The LangGraph graph stops at the orchestrator. What happens after each `call_i` is
decided by the specialist agents' routing, which differs per topology:

```mermaid
flowchart LR
    subgraph LG["Orchestrator process (LangGraph, not on the wire)"]
        direction TB
        st([START]) --> dec["decompose<br/>Ollama: split task into sub-tasks"]
        dec --> c0["call_0"]
        dec --> c1["call_1"]
        dec --> c2["call_2"]
        c0 & c1 & c2 --> syn["synthesize<br/>Ollama: final answer"]
        syn --> en([END])
    end

    subgraph WIRE["Captured A2A traffic (ports 8001-8003)"]
        direction TB
        EX["executor :8001"]
        RE["retriever :8002<br/>3 internal retrieval phases"]
        VA["validator :8003"]
    end

    c0 -- "star · chain · mesh" --> EX
    c1 -- "star · mesh" --> RE
    c2 -- "star only" --> VA
    EX -- "chain · mesh: forward, relay SSE back" --> RE
    RE -- "chain · mesh: forward, relay SSE back" --> VA
```

| Topology | Orchestrator calls (`call_i`) | Specialist-to-specialist hops |
|---|---|---|
| star | executor, retriever, validator (all leaves) | none |
| chain | executor | executor → retriever → validator |
| mesh | executor, retriever | executor → retriever → validator (retriever has two inbound flows) |

## 3. One traced task (chain topology)

Every arrow between agents is an HTTP request on a captured port; the SSE replies stream back
along the same connections. The capture keeps packet headers only, so the observer sees
timing, sizes and direction of these exchanges, never their content.

```mermaid
sequenceDiagram
    autonumber
    participant C as Collector
    participant O as Orchestrator
    participant E as Executor :8001
    participant R as Retriever :8002
    participant V as Validator :8003
    participant L as Ollama

    C->>C: start tcpdump on lo0 (snaplen 96)
    C->>O: handle_task(prompt)
    O->>L: decompose (local, not captured)
    O->>E: GET agent card, POST message/stream
    E->>L: execute (blocking)
    E->>R: POST message/stream (executor output)
    R->>L: retrieval phases 1-3
    R->>V: POST message/stream (retrieved context)
    V->>L: validate (streaming)
    V-->>R: SSE status chunks + result artifact
    R-->>E: relayed SSE chunks + artifact
    E-->>O: relayed SSE chunks + artifact
    O->>L: synthesize (local, not captured)
    O-->>C: final answer
    C->>C: stop capture, write .pcap + .json sidecar
```
